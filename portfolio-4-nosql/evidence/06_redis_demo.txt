R1. LOGIN SESSIONS: a key that deletes itself after 15 minutes of inactivity
======================================================================
redis> SET session:9f2c41d7e8 {"customerId":1015,"deviceId":"dev-694cac15d72d","kycTier":2} EX 900
        OK
redis> GET session:9f2c41d7e8
        "{\"customerId\":1015,\"deviceId\":\"dev-694cac15d72d\",\"kycTier\":2}"
redis> TTL session:9f2c41d7e8
        (integer) 900
  Each API call slides the expiry forward (keep-alive):

        (integer) 1

        (integer) 4

        "2"

        (integer) 1

R2. ONE-TIME PASSWORDS (OTP) for transfer confirmation
======================================================================
  SET ... NX only succeeds if no OTP is active, which stops repeated OTP requests flooding the customer:
redis> SET otp:+2348100001000 482913 EX 120 NX
        OK
redis> SET otp:+2348100001000 111111 EX 120 NX
        (nil)
  Wrong guesses are counted; the counter expires on its own:
redis> INCR otp_attempts:+2348100001000
        (integer) 1
redis> INCR otp_attempts:+2348100001000
        (integer) 2
redis> INCR otp_attempts:+2348100001000
        (integer) 3
redis> EXPIRE otp_attempts:+2348100001000 900
        (integer) 1
  (the application refuses further guesses once the counter reaches 3)
  Correct code: verify, then DEL so the code cannot be used twice:
redis> GET otp:+2348100001000
        "482913"
redis> DEL otp:+2348100001000
        (integer) 1
  Expiry in action, with an OTP of 2 seconds:
redis> SET otp:demo 999999 EX 2
        OK
redis> GET otp:demo
        (nil)

R3. RATE LIMITING: at most 5 transfers per customer per minute
======================================================================
  A Lua script makes INCR + EXPIRE ONE atomic step on the server, so two app servers
  cannot both see count = 5 and let a 6th transfer through:
   transfer attempt 1  ->  count in this minute = 1  ->  ALLOWED
   transfer attempt 2  ->  count in this minute = 2  ->  ALLOWED
   transfer attempt 3  ->  count in this minute = 3  ->  ALLOWED
   transfer attempt 4  ->  count in this minute = 4  ->  ALLOWED
   transfer attempt 5  ->  count in this minute = 5  ->  ALLOWED
   transfer attempt 6  ->  count in this minute = 6  ->  BLOCKED (429 Too Many Requests)
   transfer attempt 7  ->  count in this minute = 7  ->  BLOCKED (429 Too Many Requests)

R8. WHY THE LEDGER STAYS IN POSTGRESQL
======================================================================
redis> CONFIG GET appendonly
        1) "appendonly"
        2) "no"
redis> CONFIG GET save
        1) "save"
        2) "3600 1 300 100 60 10000"
        rdb_changes_since_last_save:402952
        rdb_last_save_time:1793786582
        aof_enabled:0
  With the default settings Redis persists only periodic snapshots (RDB), and the
  append-only file is OFF. A crash can lose the writes since the last snapshot,
  which is acceptable for sessions, OTPs and counters, and unacceptable for money.
