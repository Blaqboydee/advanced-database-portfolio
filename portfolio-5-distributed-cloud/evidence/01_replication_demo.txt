R6. THE PRICE OF CONSISTENCY: deposit throughput, 8 clients, three commit modes
======================================================================
  3 rounds; within each round the modes run one after another for 6 s each, so background
  load on the laptop affects all modes alike. The MEDIAN of the 3 rounds is reported.
  mode                                               tps per round              median tps  median latency  vs async
  ASYNC (no synchronous standby)                     4,323, 2,967, 2,812             2,967         2.70 ms       +0%
  SYNC  remote flush (replica1 has it on disk)       2,152, 2,431, 2,515             2,431         3.29 ms      -18%
  SYNC  remote apply (replica1 can already READ it)  1,932, 1,423, 1,865             1,865         4.29 ms      -37%
  -> every synchronous commit pays an extra round trip to replica1 (and, for remote_apply,
     waits for it to replay). Here all containers share one laptop, so the round trip is
     tiny; between data centres it adds the network latency to EVERY commit.
